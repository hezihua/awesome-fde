## 一、技术地图（操作版）

| 层 | 做什么 |
| --- | --- |
| 地基 | 目录分类、标签、元数据（来源、时长、链接） |
| 文本 | 统一成 Markdown，方便模型读 |
| 关联 | Wiki 双向链接、MOC 导航 |
| 检索 | 关键词 → RAG / 混合检索 |
| 更深层 | 知识图谱、本体论 |

今天只走完「能用的小库」。客户真实资料不能外泄，课上用模拟包带练。

## 二、从一个业务问题开始

例：广告带货的内容公司，要「老带新」——老人时间解放，新人自己查库，入职培训交给 AI。前提不是先搓智能体，而是**先有一套清晰完整的知识库**。

客户需求往往很糊。落地前先盘：

- 有哪些岗位，各干什么
- 每个岗位的工作流程
- 带新人时最常被问的问题集

没有问题盘点，就不知道库里该放什么。

## 三、现场真实情况

客户给你的东西通常是：

- 没有文档
- 或一堆扫描件、聊天记录、过期 PPT
- OCR 识别还带错字

所以步骤是：

1. **补齐**：缺的 SOP 约同事重写；写不动就录音转写再提炼
2. **清洗**：格式统一成 Markdown，这一步可以交给 AI
3. **核对**：业务逻辑必须面对面跟业务人员过，标准、格式、重点让负责人签字式反馈
4. **挖脑子**：老员工至少半小时，常见是数个下午

签单时就要写清分工：手册由客户内部提供，你负责结构、清洗和装库。想从 0 到 1 全包，很难成交也很难交付。

## 四、装库顺序

```
MD 清洗 → 目录分类 → Wiki 双向链接 → MOC 导航 → 检索测试题
```

MOC（Map of Content）是给人导航的目录页，也给 Agent 一个入口文件。另建一个「检索测试」文件夹，用真实问题回归，避免库搭完没人验。

## 五、给学员的作业方向

下一节用「杭州导游知识库」把这条流程再走一遍，并加上 RAG 原理。自己练习时选一个**岗位级**问题，不要一上来做全公司本体论。
