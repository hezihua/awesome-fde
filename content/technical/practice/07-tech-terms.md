## 一、模型是怎么炼出来的

```
互联网文本 / 代码 / 论文
        ↓ 清洗（去重、过滤、规范化，常整理成 Markdown）
      Token（文字变成机器能算的数字）
        ↓
 Transformer（2017，《Attention Is All You Need》）
        ↓ 预训练：预测下一个 Token
    Base Model（聪明但没情商的「小白」）
        ↓ 后训练 Post-training（言传身教）
      上架的 LLM（Kimi / GLM / DeepSeek …）
```

GPT 里的 T，就是 Transformer。预训练只做一件事：给定上文，猜下一个 Token 的最高概率。「今天天气很」后面最常接「好」。

## 二、提示词为什么叫提示词

模型在做条件概率。你写提示词，就是在改它下一步的概率分布。一套能用的结构至少四块：

1. **任务**：到底要它做什么
2. **背景 / Context**：前因后果
3. **约束**：格式、长度、不能做什么
4. **示例**：好样本比形容词更管用

大语言模型：你给一段文字，它回一段文字。同一套机制扩到图、音、视频，就是 AIGC。

## 三、上下文工程 = 把记录变成 Prompt

最早的上下文工程很朴素：把聊天记录打包，再当提示词送进模型。后面所有形态（知识库、RAG、联网搜索）都是同一条主线：

**Token ← Prompt ← 优质上下文**

模型有训练截止日期。截止日期之后的事实，不开联网搜索它就不知道。联网搜索本质仍是：补一块更准的上下文。

## 四、随机性和幻觉从哪来

Token 预测是猜。猜就会猜错。 drift（漂移）是同一套提示词，换窗口、换日期，答案不一样。这就是第 1 节说的「不确定」。工程上能做的是：

- 收紧提示词和知识库
- 用检索代替让模型「回忆」
- 加校验、人工终审，而不是幻想零幻觉

## 五、从聊天到干活

2025 年的两条路：

- **Coding 路线**：Function / Tool Calling，Cursor 这类 IDE
- **能写代码就能控电脑**：演示里按一下唤出 Claude Code，老板立刻懂

Skill 规范跟着 Claude Code 在 2025 下半年出现。2026 年初 OpenClaw 火过一阵，但纯 Vibe Coding 出来的本机 Agent 有安全漏洞，不能当企业默认方案。

能写代码 ≠ 能上线。第 1 节说的「花瓶和屎山」，根子多半是前期 **Plan / 架构**没想清楚。

## 六、给老板的三句话

1. 模型是「猜下一个字」的机器，不是真理机器
2. 你给的上下文越干净，它猜得越准
3. Agent 比网页聊天强在能动手，不强在更不会说错
