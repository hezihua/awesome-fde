> **课程来源**：FDE 实战训练营第一期 · 第 10 节
> **时长**：约 1 小时 15 分
> **位置**：AKA 里的第二个 **A · Automation**

Agent 解决「能干活」，知识库解决「知道怎么干」，自动化解决「让它自己去干」。

中小公司的「数据库」多数用飞书多维表格或企微智能表格就够，工程级库放到制造业 / 电商 / 集团 ERP 再谈。

## 一、自动化的三代

### 1. RPA：模仿点击

第一步点什么，第二步点什么。例子：打开抖音创作者中心 → 数据中心 → 作品数据 → 导出。

课上用 WorkBuddy + 浏览器自动化 / CDP / Browser Skill，一点运行就按人类路径把数据下下来。Computer Use 很大一块底层也是 RPA。

适合：**步骤固定、界面稳定**。

### 2. Workflow：加上判断

步骤之间出现条件、分支、定时触发。典型产品：n8n、扣子、飞书多维表格自动化。

本质是编码，但封装成组件，普通人拖一拖：定时 20:30 发一条消息，就是最小工作流。

问题：对人的要求仍然不低。大公司里真会搭的人不多。

### 3. Skill：下命令就好

Workflow 太重时，把流程写成 Agent 能读的说明书，语音或一句话触发。Skill 规范从 Claude Code 一带出来，现在是企业交付的主流封装方式。

## 二、Skill 里面有什么

核心文件是 `SKILL.md`，**本质上是一套提示词**。课上举过年初的 `agent-team-manager`：打开就是一篇结构化说明。

常见构成：

- `SKILL.md`：角色、步骤、边界、输出格式
- 脚本 / 资源：真要跑的代码、模板
- 触发方式：对话、定时、飞书机器人

写 Skill 不是炫技，是把「熟练员工脑子里的 1、2、3」写成模型不容易跑偏的操作手册。

## 三、怎么选型

| 情况 | 用什么 |
| --- | --- |
| 界面点击、导出报表 | RPA / 浏览器 Skill |
| 有审批、有分支、要通知多人 | 飞书 / n8n Workflow |
| 要复用、要培训、要交给客户自己跑 | Skill |
| 客户完全不会搭工作流 | 不要逼他们学 n8n，封装成 Skill |

## 四、和前面的衔接

没有第 8、9 节的知识库，自动化只会稳定地做错事。先 K 后 A，顺序不要反。
