## 一、知识库是工具，不是目的

搭库之前先问：客户为什么需要它？要覆盖哪些问题？

杭州导游作业对应一家景点相关公司时，至少四类需求：

1. 景点推荐（特色、季节、政策、价格）
2. 路线规划（机场 / 火车站 / 地铁，一日游 / 两日游）
3. 预算盘点
4. 真实种草（小红书经验帖）

把这些写成提示词，再发给 WorkBuddy，比「把一堆资料丢进去」重要。中间的拆解过程，才是 FDE 要练的能力。

## 二、和 Agent 协作的节奏

课上的选择示例：

- 载体：飞书多维表格（也可 Obsidian / 本地 Markdown）
- 范围：杭州市区
- 种草采集：MCP 半自动
- 交付：先做最小可用样板，再扩

WorkBuddy 对飞书、钉钉、企微有连接器，授权后可以直接读写。来源标注、检索测试题单独建文件夹。

常用降维提示词：**「用村口 60 岁大爷也能听懂的话解释」**。把 RAG、切片、向量化讲成人话，客户才肯继续听。

## 三、RAG 的大白话

| 术语 | 人话 |
| --- | --- |
| Markdown | AI 最顺眼的统一草稿纸。PPT / PDF / 录音都先变成它 |
| 切片 | 公司台账太厚，撕成一张张小纸片 |
| 向量化 | 每张纸片按一个「指纹」 |
| 检索 | 按指纹找最像的几张 |
| RAG | 开卷考试：先找到纸条，再对着纸条回答 |

没有检索的对话是闭卷，模型只能靠训练记忆猜。有 RAG 就像请了课程助教，可以按资料互动。

## 四、作业标准（即使被删过仍该有）

原版作业写得很细，例如：

- 杭州景点库不少于 12 个点
- 每个点写清名称、类型、推荐季节等

直接把整份标准丢给模型也能做，但你会丢掉「自己拆问题」的训练。FDE 卖的是拆解，不是提示词粘贴。

## 五、进阶

需求清楚之后，可以再包 Skill，甚至做成网页应用。那是加分项。主路径永远是：

**问题清单 → 资料补齐 → MD → 目录 / 链接 → 检索测试 → 必要时再上 RAG。**
