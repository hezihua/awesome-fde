## 一、为什么先做 K

自动化建立在「工作步骤和公司资料已经清楚」之上。没有知识库，Agent 不知道 1、2、3 步怎么走，Automation 也搭不起来。

新手最容易犯的错：把知识库当收藏夹，疯狂往里丢链接，最后「收藏进收藏夹吃灰」。囤积感 ≠ 可用上下文。

## 二、优质上下文的四个标准

| 标准 | 要求 |
| --- | --- |
| **可追溯** | 来源网站、链接、书、段落、作者、时间；自媒体还可能记点赞收藏 |
| **可理解** | 完整：有前因有后果，不能只剩结论 |
| **可控制** | 权限：管理 / 编辑 / 只读 / 不可见。老板、助理、实习生看到的不该一样 |
| **可相信** | 有「优质」标准。每家公司细则不同，但必须有标准 |

存资料时就要打来源标签。可以做成知识库管理 Skill，换电脑时一起迁走。

## 三、数据 → 信息 → 知识 → 智慧

```
信号 / 原始数据  →  信息（发生了什么）  →  知识（规则、规律、经验）  →  智慧（判断力）
```

知识库有两个作用：

1. 让 AI **执行**：公司怎么运转、业务怎么做
2. 更核心的是辅助人 **判断**

大量规则和经验还在老员工脑子里，必须访谈、录音、梳理，才能进库。只堆官网 PDF，库是空的。

## 四、知识库 vs 数据库

| | 知识库 | 数据库 |
| --- | --- | --- |
| 形态 | 文本：行业知识、规则、方法论 | 关系：字段、类型、关联 |
| 回答 | 流程、步骤、判断标准 | 谁和谁有关、什么状态、什么日期 |
| 典型载体 | 飞书云文档、Obsidian、Markdown | 飞书多维表格、企微智能表格 |

文本只能从上到下排，索引能力有限。多维表格能做单选、多选、人员、日期、附件，把结构摊开。中小公司多数用多维表格就够，不必先上工程级数据库。

两者要一起做：知识库给「怎么想」，数据库给「现在是什么状态」。

## 五、技术地图（先认门牌）

从浅到深：

1. 目录分类、标签、元数据
2. 统一成 Markdown
3. Wiki 双向链接、MOC 导航
4. 关键词检索（软件和 Agent 几乎都自带）
5. RAG / 向量检索 / 混合检索
6. 知识图谱
7. 本体论：把公司里知识之间的关系讲清楚

基础课只要求建立这张地图。切片、向量化、开卷考试的比喻，技术课再展开。

## 六、实践提醒

- 先盘业务问题，再决定库里该有什么
- 缺的 SOP 要补：约老员工录音，比空等文档更有效
- 权限和来源从第一天就设计，后期补非常痛
